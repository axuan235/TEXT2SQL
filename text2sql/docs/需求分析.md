## 2. 关键概念

### 2.1 特征与特征 DSL
- 特征 = 实体在某个维度的具体取值（如 性别男），每个特征 DSL **只包含该字段的计算逻辑**。
- 特征 DSL 示例：`student.avg_score -> t_student.reduce('student_id', 'avg(score) as avg_score').avg_score`
- 7 个基础算子：map / reduce / filter / union / join / limit / sort。
  - union 仅支持两表合并（字段必须对应），多表逐级 `.union(t2).union(t3)`。
  - join 一次只关联一张表，关联类型与 SparkSQL 一致；单表条件走 filter。
  - reduce = shuffle 聚合 = group by。
  - map = 一行进一行出 = select 计算列（窗口函数也用 map 表达）。
  - filter 条件与 SparkSQL 一致。
  - 不支持 flatmap（几乎无一对多场景）；sort/limit 一般出现在取数阶段。
- 特征计算不记录中间字段保留情况，只记录对原表字段的处理；最终计算规划按字段依赖选用。

### 2.2 特征描述结构
`业务_主体_限定词组_(维度)属性：值域`，如 `链家访客_用户_最近三天_访问次数：>5`。
- D 业务空间（口语中一般缺省）、S 主体、C 限定词组（可缺省或多个）、O 属性。
- 结构化后拆为两部分：主体_属性（检索特征结构库）+ 限定词列表（检索限定词库）。

### 2.3 特征抽取的两个场景
- 场景1：历史模型 SQL 日志 -> 提取 DSL -> 计算优化 -> 规范统一命名 -> 拆库入库（去重）。
- 场景2：知识库未命中 -> 大模型生成 SQL -> 同一套提取流程入库。

### 2.4 计算优化
- 最优计算顺序：filter/map/union/reduce/join。
- 任意两个操作交换是否影响计算结果 —— 完整分析见 `README.md`《算子交换分析》。

## 3. 知识库设计

### 3.1 特征结构库（纯文本 JSONL）
```json
{
  "feature_struct": "t_student_score.reduce('student_id', 'avg(score) as avg_score').avg_score",
  "name": "avg_score",
  "rule_trans": "从t_student_score表中按照学生编号分组，对分数取平均值",
  "valid_tans": "",                  // 人工标注，首次写入留白
  "table_list": ["t_student_score"],
  "MD5": "..."                        // 结构体唯一ID，用于去重
}
```

### 3.2 限定词库（纯文本 JSONL）
```json
{
  "compare_struct": "grade = X",      // 参数 mask 为 X，避免检索受参数影响、减少知识库数量
  "value_type": "string",
  "rule_trans": "年级等于X",
  "valid_tans": "X年级",
  "table": "t_student_score",
  "c_md5": "..."
}
```
- 复合条件需拆为简单条件（如 `grade='2' and class='3'` -> 两条记录）。

## 4. 规则翻译

- 条件翻译：配置文件模板 + transCol/transValue/stringFormat。
  - transCol：查表字段信息表翻译列名（both_year -> 出生年）。
  - transValue：翻译补全（2010 -> 2010年）、字段映射（gender 1 -> 男）、映射字典（city_code -> 北京）。
  - stringFormat：参数列表格式化（北京、上海）。
- 函数翻译：配置文件（avg/sum/count/max/min/concat/row_number 等）。
- 特征 DSL 翻译：辅助打标（可选实现，本项目已实现）。

## 5. 特征生成流程（6 步）

1. 结构化特征描述：切分主体_属性 + 限定词列表。
2. 知识库检索：embedding 检索（未配置时字符相似度/Jaccard 兜底）；相似度过低 -> 大模型生成 SQL 后特征提取。
3. 限定词参数实例化：mask 参数按语义取值 + 表字段映射反向转换（女 -> gender=2）。
4. 候选集生成与筛选：特征结构 x 条件全量组合，表一致性约束。
5. 特征计算筛选：从候选集中选语义最佳。
6. 保留取数逻辑：`student.filter("avg_score>60 and birth_year>1999 and gender=1").limit(10)[full_name, avg_score,...]`。

## 6. 计算规划

1. 整理明细：各情况下计算路径是否具备公共基础、如何合并（README 表）。
2. 实现合并逻辑：存在多种可能性时选择最优组合（同表 + 可合并 filter + 相同 shuffle 键）。
3. 字段依赖分析，计算结构树转 SQL 模型。
4. A 聚合可升级为 A,B 聚合后再次按 A 聚合（注意1）。
5. 跨表特征自动补充 join：优先配置 `join_keys.json`，否则自动匹配同名列（注意2）。
